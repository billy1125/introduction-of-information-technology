# 投影片（.slides.md）設計規範

本規範依照 `01-History-of-Computer.slides.md` 目前的實際寫法整理而成，作為之後製作各章節 Marp 投影片版本（`0X-XXX.slides.md`）時的統一依據。若未來 `01-History-of-Computer.slides.md` 的寫法有調整，應同步回來更新本文件。

投影片版本與正文 `.md` 是兩份獨立文件，各自服務不同用途（正文供閱讀、投影片供上課簡報），排版規則不完全相同，詳見文末〈與正文 `.md` 的差異〉。

## 1. Frontmatter

每份 `.slides.md` 開頭固定寫法：

```markdown
---
marp: true
theme: gaia
paginate: true
class: invert
style: |
  img {
    display: block;
    margin-left: auto;
    margin-right: auto;
  }
---
```

- `class: invert`：使用深色主題。
- `style` 區塊讓所有內文圖片自動置中，不需要每張圖片手動加對齊語法。

## 2. 分頁符號

每張投影片之間用單獨一行 `---` 分隔，前後各留一個空行：

```markdown
上一頁最後一行內容

---

下一頁第一行內容
```

## 3. 封面頁

整份簡報第一頁只有主標題與一行副標說明，不加其他內容：

```markdown
# 計算機歷史與資訊科技概論

從最早的計算工具，到電子計算機、網際網路，再到今天的 AI

---
```

## 4. 開場鉤子（前言）區塊

僅出現在整份簡報最前面一次（不是每章重複），目的是用情境與痛點引起學生興趣，再帶出本課程能帶來的能力。固定包含四張投影片：

1. `## 前言：從...談起`：一個貼近學生生活或職場的情境故事
2. `## 不懂 XX，你可能會...`：條列式痛點
3. `## 懂 XX，你可以...`：條列式能力，最後加一句整句粗體的 blockquote 點出核心價值
4. 一張「你習以為常的功能」對照「背後的發展歷程/技術」的表格

## 5. 章節分隔頁

每個章節開始時，用一張只有標題與 1–2 段引言文字的投影片作為該章節封面，**不加 `##` 副標、不加條列**：

```markdown
# 二、早期資訊處理與計算工具

在電子計算機出現之前，人類已發展數千年的計算工具，從手指計數、結繩記事到算盤、計算尺，每一項工具都反映當時社會對「加快計算速度、減少人為錯誤」的需求。

本章帶你認識這些早期工具的原理與限制，理解「計算工具」與「計算機」之間的差異。

---
```

- 標題格式固定為 `# {中文數字}、{章節名稱}`，與正文 `.md` 的章節標題一致。
- 引言為 1–2 段散文（每段 1–3 句），不是條列，內容說明「本章要學什麼」與「為什麼重要」，語氣像對學生說話。

## 6. 內容頁

每張內容頁固定用 `## 子標題` 開頭，接一種或多種內容區塊：

- **條列**：`- **關鍵詞（English Term）**：說明文字`
- **表格**：用於比較兩個以上的技術/世代/方案
- **編號步驟**：`1. 2. 3.`，用於有先後順序的流程
- **短段落**：一兩句純文字說明，不一定要條列化
- **Fenced code block**：畫簡單的流程箭頭圖（例如 `資料 → 資訊 → 知識`），非真正程式碼

一張投影片通常只放一種主要內容區塊，避免資訊過密。

## 7. 粗體與行內強調慣例

- 專有名詞第一次出現：`**中文名詞（English Term）**`，例如 `**資料（Data）**`、`**人工智慧（AI）**`。
- 一般強調關鍵字也用 `**...**`，不需要額外加底線或斜體。
- 善用全形標點做語氣區分：「」標示引用詞彙或術語、——標示插入說明、→ 標示流程或演進關係。

## 8. Blockquote 慣例

每頁最多一個 blockquote，用於整頁的重點總結或金句，**整句都要粗體**，不要只加粗部分詞語：

```markdown
> **工業例子：溫度／轉速數字是資料；「本班次不良率 3%」是資訊；「轉速超過 2000 轉不良率上升」是能預防性維護的知識**
```

若原本句子裡有局部粗體的專有名詞，改成整句粗體時要拿掉內層的 `**`，避免巢狀星號在 Marp/CommonMark 中解析錯誤：

```markdown
<!-- 錯誤：巢狀粗體 -->
> **廣義而言，**計算機（Computer）**：任何能接受輸入、執行處理、產生輸出的裝置**

<!-- 正確 -->
> **廣義而言，計算機（Computer）：任何能接受輸入、執行處理、產生輸出的裝置**
```

## 9. 圖片版式（三種模式）

### 9.1 整頁大圖

圖片獨占一頁，通常是總覽/整理型的圖表：

```markdown
<!-- ## 電腦世代演進總覽 -->

![h:600](images/01-History-of-Computer/computer-generations.png)

---
```

- 固定使用 `h:600` 控制高度。
- 上方可加一行**被註解掉**的標題 `<!-- ## 標題 -->`，不會實際渲染，只用於作者辨識這張圖對應的主題，方便日後編輯。

### 9.2 左右背景圖 + 文字

介紹單一文物、人物或設備時使用，圖片佔頁面左側或右側 45% 當背景，另一側放標題與說明：

```markdown
![bg right:45%](images/01-History-of-Computer/ishango-bone.jpg)

## 伊尚戈骨頭

- 目前已知最古老的計數骨頭
- 距今約兩萬年
- 上面刻有一系列刻痕
- 可能是人類早期的計數或曆法紀錄

---
```

- 左右交錯使用 `bg left:45%` / `bg right:45%`，避免整份簡報圖片都在同一側。

### 9.3 文中右側小圖

與段落文字同頁，圖片以縮圖形式靠右，用於為文字內容補充一張示意圖但不需要整頁篇幅：

```markdown
## 技術演進的脈絡

![right:40%](images/01-History-of-Computer/age-of-computer.png)

每個時代都建立在前一個時代的基礎上，且演進速度越來越快：

- 算盤被使用了數千年
- 電腦世代每十年就迭代一次
- AI 技術以年為單位快速突破

---
```

### 9.4 圖片路徑規則

沿用正文 `.md` 的規則：路徑為 `images/{對應章節檔名}/{kebab-case 檔名}.png|jpg`，例如 `images/01-History-of-Computer/vacuum-tube.jpg`。

## 與正文 `.md` 的差異

- **不加圖片來源圖說**：正文 `.md` 每張圖片下方需標註來源（自製或外部授權），但投影片版本追求畫面乾淨、上課節奏流暢，**不在投影片上顯示圖說文字**。圖片授權仍須在正文對應圖片處完整標註，投影片只是重複使用同一張已確認授權的圖片。
- 投影片沒有頁碼隱藏機制：所有頁面統一使用 frontmatter 的 `paginate: true`，不對個別頁面做例外處理。

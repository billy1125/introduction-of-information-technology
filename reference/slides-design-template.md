# 投影片設計規範

本檔為各章節投影片版本（`0X-XXX.slides.md`）的統一設計規範，不綁定特定課程或學科領域。投影片以 [Marp](https://marp.app/) 撰寫，在 VS Code 中安裝 Marp for VS Code 擴充套件即可預覽與匯出 PDF。

製作新章節投影片時，複製 `reference/slides-template.slides.md` 作為起點，並依本檔調整內容。投影片是正文的濃縮版，正文的撰寫規範（用語、中英夾雜空白、粗體標記前後空白、圖片路徑與檔名）同樣適用，見 `reference/chapter-writing-guide.md`；本檔只記錄投影片特有的規則。課程名稱、章節標題副標等隨課程而異的設定，見專案的 `CLAUDE.md`。

## 一、Frontmatter

每份投影片檔案開頭固定為下列 frontmatter，四個設定值不可更動：`marp: true` 啟用 Marp、`theme: gaia` 指定佈景主題、`paginate: true` 顯示頁碼、`class: invert` 套用深色底色。

`style` 區塊有兩條規則，兩條都不可省略，第三點是刻意留下的例外：

- **圖片置中**：讓所有圖片自動水平置中，缺少它時圖片會靠左，整份投影片的版面會不一致。
- **主文降一級**：`gaia` 主題的 `section` 基準字級是 35px，對條列與表格偏大，一頁塞不了幾項。這條規則把主文降到 `0.85em`（約 29.75px），標題（h1 1.8em、h2 1.5em）維持原大小，維持標題與內文的層次對比。選擇器一律用子選擇器 `section > …`，只作用於投影片的第一層區塊；若寫成 `section p` 這類後代選擇器，blockquote 裡的段落、巢狀清單的項目會被重複套用而越縮越小。
- **程式碼區塊不套用**：`gaia` 已將 `pre code` 設為 `.7em`（約 24.5px），若再乘 0.85 會掉到約 20.8px，投影時看不清楚，因此規則中不含 `section > pre`。

```yaml
---
marp: true
theme: gaia
paginate: true
class: invert
style: |
  img {
    display: block;
    margin-left: auto;
    margin-right: auto;
  }
  section > p,
  section > ul,
  section > ol,
  section > table,
  section > blockquote {
    font-size: 0.85em;
  }
---
```

頁碼統一由 `paginate: true` 控制，不對個別頁面做隱藏或例外處理。

## 二、分頁符號

每張投影片之間用單獨一行 `---` 分隔，前後各留一個空行。少了空行，Marp 有機會把 `---` 解讀成前一行文字的底線標題語法而不分頁。

```markdown
上一頁最後一行內容

---

下一頁第一行內容
```

## 三、封面頁

整份簡報第一頁只放主標題與一行副標說明，不加其他內容。副標的作用是用一句話交代這份簡報的跨度或主軸，讓聽眾在第一眼就知道接下來要走多遠。

```markdown
# {簡報主標題}

{一行副標，說明本份簡報的跨度或主軸}
```

## 四、開場鉤子

只出現在整份簡報最前面一次，不在每章重複。目的是先用情境與痛點引起興趣，再帶出學完之後能獲得的能力。固定包含四張投影片：

1. `## 前言：從{貼近聽眾日常的切入點}談起`——一個貼近學生生活或職場的情境故事
2. `## 不懂{本主題}，你可能會⋯⋯`——條列式痛點
3. `## 懂{本主題}，你可以⋯⋯`——條列式能力，最後加一句整句粗體的 blockquote 點出核心價值
4. 一張表格，左欄是「你習以為常的功能」，右欄是「背後的發展歷程或技術」

## 五、章節分隔頁

每個章節開頭需有一張分隔頁，內容只有 `# {中文數字}、章節標題`（與正文 `.md` 的章節標題一致）與 **1–2 段引言散文**，說明本章要學什麼、為什麼重要。每段 1–3 句，語氣像對學生說話。

分隔頁不加 `##` 副標，也不使用條列。引言的作用是讓聽眾在進入細節前先建立動機，條列做不到這件事——條列會被讀成待辦事項，散文才會被讀成脈絡。

```markdown
✅
# 三、{章節標題}

{一段引言散文，點出本章要回答的核心問題，以及它為什麼不像表面上那麼簡單。用具體的疑問或反直覺的事實起頭，比用定義起頭更能建立動機。}

{第二段引言，說明本章的推進路線：從哪裡出發、經過什麼、收在哪裡。}

❌
# 三、{章節標題}
## 本節大綱
- {子題一}
- {子題二}
- {子題三}
```

## 六、內容頁

每張內容頁固定以 `## 子標題` 開頭，接下列其中一種內容區塊。一張投影片通常只放一種主要區塊，避免資訊過密：

| 區塊 | 用途 |
|---|---|
| 條列 | 格式為 `- **關鍵詞（English Term）**：說明文字` |
| 表格 | 比較兩個以上的技術、世代或方案 |
| 編號步驟 | `1. 2. 3.`，用於有先後順序的流程 |
| 短段落 | 一兩句純文字說明，不一定要條列化 |
| Fenced code block | 畫簡單的流程箭頭圖（例如 `資料 → 資訊 → 知識`），非真正程式碼 |

## 七、粗體與行內強調

專有名詞第一次出現寫成 `**中文名詞（English Term）**`；一般強調關鍵字同樣用 `**⋯⋯**`，不另外加底線或斜體。

善用全形標點做語氣區分：「」標示引用的詞彙或術語、——標示插入說明、→ 標示流程或演進關係。

## 八、Blockquote

每頁最多一個 blockquote，用於整頁的重點總結或金句。Blockquote（`>`）一律 **整句粗體**，不可只加粗其中部分詞語，也不可出現巢狀 `**`。投影片上的 blockquote 用來呈現需要被記住的一句話，整句同一種強調層級才有效；句中再挑幾個字加粗，會讓視覺焦點散掉，而且巢狀 `**` 在 Marp 的渲染結果不穩定。

若原本句子裡有局部粗體的專有名詞，改成整句粗體時要拿掉內層的 `**`。

```markdown
✅ > **工具會一直換，但解決問題的方法會留下來。**
❌ > 工具會一直換，但解決問題的 **方法** 會 **留下來**。
❌ > **工具會一直換，但解決問題的 **方法** 會留下來。**
```

## 九、圖片版式

投影片的圖片依用途分三種版式，不要自行混搭其他寫法：

| 版式 | 語法 | 使用時機 |
|---|---|---|
| 整頁大圖 | `![h:600](path)` | 圖本身就是這一頁的主角，例如完整的流程圖或架構圖，文字只留標題 |
| 左右背景圖＋文字 | `![bg left:45%](path)` 或 `![bg right:45%](path)` | 圖與文字份量相當，需要對照閱讀 |
| 文中右側小圖 | `![right:40%](path)` | 文字為主，圖只是輔助說明 |

整頁大圖的高度可依實際圖片比例在 `h:500` 到 `h:600` 之間微調，但同一份投影片內應維持一致。背景圖與小圖的百分比同理，不要每一頁都用不同數值。

圖形明顯寬扁時（例如橫向展開的流程圖或狀態機示意圖），改用 `![w:700]` 以寬度控制，否則限制高度會讓圖橫向溢出畫面。同一份投影片內以高度控制為主，寬度控制只用在確實需要的那幾張圖。

整頁大圖的上方可加一行 **被註解掉** 的標題 `<!-- ## 標題 -->`，不會實際渲染，只用於作者辨識這張圖對應的主題，方便日後編輯。

左右背景圖應交錯使用 `bg left:45%` 與 `bg right:45%`，避免整份簡報的圖片都擠在同一側。

圖片路徑與檔名沿用正文 `.md` 的規則（`images/{本章檔名}/{kebab-case 檔名}.png`），見 `reference/chapter-writing-guide.md`〈五、圖片〉。

## 十、不加圖片來源圖說

投影片版本 **不加圖片來源圖說**，這是與正文 `.md` 最大的差異。投影片的版面空間有限，一行小字的來源標註在投影時多半看不清楚，反而擠壓內容。

圖片的授權標註仍以正文為準：同一張圖只要在正文 `.md` 中依規範標註了來源、作者與授權條款，投影片即可直接引用。若某張圖只出現在投影片而未出現在正文，仍須確認其授權，並在正文或 `README.md` 的授權例外清單中補上記錄。

## 十一、每頁資訊量

投影片是講述的輔助工具而非講稿。每頁以一個概念為原則，條列不超過五項、每項不超過兩行；需要長篇說明的內容留在正文 `.md`，投影片上只放能被口頭展開的關鍵詞。若一頁的內容需要縮小字級才塞得下，正確的做法是拆成兩頁，而不是調整字級。
